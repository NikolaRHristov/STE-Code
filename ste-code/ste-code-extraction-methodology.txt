# STE-Code Extraction Methodology
# Turn-by-turn protocol for processing code documents

## Overview

This protocol describes how to process a code document (README, API spec, code review,
commit message, etc.) turn by turn, extracting non-compliant text and transforming it
into STE-Code compliant output.

## Turn Structure

Each turn has three phases:

### Phase A: Classification

1. Identify the document type:
   - PROCEDURAL: commit messages, setup guides, runbooks, code review instructions
   - DESCRIPTIVE: README files, API documentation, architecture descriptions
   - SAFETY: changelogs, migration guides, deprecation notices
   - MIXED: documents containing multiple types

2. Apply the applicable word count limit:
   - PROCEDURAL: 20 words per sentence (Rule 5.1)
   - DESCRIPTIVE: 25 words per sentence (Rule 6.3)
   - SAFETY: 20 words per sentence (Rule 5.1, applied to safety instructions)

### Phase B: Extraction and Transformation

Apply the 6-pass pipeline:

**Pass 1 — Lexical Lookup:**
Read one sentence. Tokenize on whitespace and punctuation boundaries.
For each word, check the STE-Code dictionary:
- APPROVED: word is in the dictionary as approved.
- UNAPPROVED: word is in the dictionary as not approved.
- TECHNICAL_NOUN: word fits a Technical Code Noun category (Rule 1.5).
- TECHNICAL_VERB: word fits a Technical Code Verb category (Rule 1.12).
- UNKNOWN: word is not in the dictionary and needs classification.

**Pass 2 — Classification:**
For each UNKNOWN word:
- Can it fit in a Technical Code Noun category? If yes, mark TECHNICAL_NOUN.
- Can it fit in a Technical Code Verb category? If yes, mark TECHNICAL_VERB.
- Is it a function name, variable name, class name, or module name?
  If yes, mark TECHNICAL_NOUN (category 6: Modules, classes, and components).
- Otherwise: mark for replacement.

**Pass 3 — POS Lock:**
For each APPROVED word, verify part of speech matches dictionary specification.
For each TECHNICAL_NOUN: verify it is used as a noun (Rule 1.7).
For each TECHNICAL_VERB: verify it is used as a verb (Rule 1.13).

**Pass 4 — Meaning Validation:**
For each APPROVED word, verify the context matches the approved meaning.
Check the polysemy resolution table for ambiguous words.

**Pass 5 — Grammar Enforcement:**
Verify verb forms (Rules 3.1–3.5).
Verify voice (Rule 3.6): active required unless agent unknown.
Verify sentence length against document type limit.
Verify compound identifiers are ≤ 3 components (Rule 2.1).

**Pass 6 — Consistency Check:**
Scan the full document for inconsistent Technical Code Noun usage (Rule 1.11).
Scan for undefined abbreviations.
Scan for jargon/slang (Rule 1.10).
Scan for phrasal verbs (Rule 9.3).
Scan for Latin abbreviations (GR-6).

### Phase C: Output

Format the transformed text using the standard output format:

```
## DOCUMENT TYPE: [PROCEDURAL / DESCRIPTIVE / SAFETY / MIXED]

## COMPLIANCE STATUS: [COMPLIANT / NON-COMPLIANT]

## TRANSFORMATION LOG:
- Pass 1 (Lexical): [X words classified: Y APPROVED, Z UNAPPROVED, ...]
- Pass 2 (Classification): [X words reclassified as TECHNICAL_NOUN/VERB]
- Pass 3 (POS Lock): [X violations found and corrected]
- Pass 4 (Meaning): [X polysemy resolutions applied]
- Pass 5 (Grammar): [X grammar violations corrected]
- Pass 6 (Consistency): [X consistency issues resolved]

## STE-CODE OUTPUT:
[The compliant text]

## OPTIMIZATIONS:
- [Optional improvements]
```

## Multi-Turn State

Carry forward across turns:
- Detected Technical Code Nouns and their categories
- Detected Technical Code Verbs and their categories
- Defined abbreviations
- Current document type and word limits
- Pending consistency issues

## Edge Cases

**Quoted text (Rule 8.6):** Code literals, error messages, and display text are quoted.
Do not transform quoted text. Count it as one word.

**Code blocks:** Treat code blocks as quoted text. Do not transform them.
Count the entire block as one word per logical line.

**Mixed language:** If a document contains non-English text, flag it but do not
transform it. STE-Code applies only to English text.

**Ambiguous classification:** When a word could be both a Technical Code Noun and
a Technical Code Verb, prefer the classification that results in fewer changes.
If in doubt, classify as Technical Code Noun (more restrictive).
