# Rule 3.4 — Do not use auxiliary verbs to make complex verb constructions.

> **Source:** Adapted from ASD-STE100 Issue 9, Rule 3.4

> Source: master.md#sec3-rule3.4

## Original Rule

Do not use the past participle form as a verb form together with the auxiliary verb "have." This construction will make a tense that is not approved.

> **Non-STE:** The operator has adjusted the linkage. (The present perfect tense is not approved.)
>
> **STE:** The operator adjusted the linkage. (The simple past tense is approved.)

Some complex verb constructions include other auxiliary verbs with the past participle form as a verb. Sentences with these constructions become complex sentences in the passive voice.

> **Non-STE:** The seat is to be installed before you install the cushion
>
> **STE:** Before you install the cushion, install the seat.
>
> **Non-STE:** The volume control can be adjusted.
>
> **STE:** You can adjust the volume control.
>
> **Non-STE:** The temperature must be adjusted.
>
> **STE:** Adjust the temperature.
>
> **Non-STE:** The sleeve will be adjusted by the robot.
>
> **STE:** The robot will adjust the sleeve.

## STE-Code Adaptation

Do not use the past participle form as a verb form together with the auxiliary verb "have." This construction will make a tense that is not approved.

Some complex verb constructions include other auxiliary verbs with the past participle form as a verb. Sentences with these constructions become complex sentences in the passive voice.

**Two patterns to avoid**

1. **The "have" + past participle (present perfect) construction.**
   Do not write "the build has compiled" or "the job has finished." Use the simple past tense instead: "the build compiled," "the job finished." The approved tenses are the simple present, simple past, and simple future only. See Rule 3.2.

2. **The passive-voice auxiliary constructions.**
   Do not write "the migration is to be run," "the cache can be cleared," "the timeout must be set," or "the report will be generated by the scheduler." These hide the actor and add words. Rewrite them as active-voice commands or statements with a named actor.

**How to rewrite a complex construction**

- **"is/are to be <verb>-ed" → a command or an active statement.**
  "The test is to be run before you commit" becomes "Before you commit, run the test."
- **"can be <verb>-ed" → name the actor and use "can".**
  "The cache can be cleared" becomes "You can clear the cache." (Or "The user can clear the cache.")
- **"must be <verb>-ed" → a command.**
  "The timeout must be set before the job starts" becomes "Set the timeout before the job starts."
- **"will be <verb>-ed by <actor>" → simple future, actor first.**
  "The report will be generated by the scheduler" becomes "The scheduler will generate the report."

**How to convert present perfect to simple past**

| Non-STE (present perfect) | STE (simple past) |
|---|---|
| The service has started. | The service started. |
| The worker has processed the queue. | The worker processed the queue. |
| The client has connected. | The client connected. |
| The job has failed. | The job failed. |

**When a past participle is correct (not a verb)**

Use the past participle as an adjective only, never as a verb with an auxiliary. "The compiled module," "the parsed file," and "the deprecated method" are correct because the participle is an adjective. See Rule 3.3. Do not write "the module has compiled" (verb) — write "the module compiled" (simple past) or "the compiled module is ready" (adjective).

**Why this rule helps code writing**

Complex verb constructions make docs longer and hide who does the action. A reader of a README, a runbook, or a code comment wants a direct command or a clear statement with a named actor. The simple tenses and the active voice are shorter and easier to translate and to scan.

## Examples

> *Adapted from spec pair:* Non-STE: The operator has adjusted the linkage.  |  STE: The operator adjusted the linkage.

> **Non-STE:** The build has compiled the module before the test runs. (The present perfect tense is not approved.)
> **STE:** The build compiled the module. Then the test runs. (The simple past tense is approved.)
>
> *Adapted from spec pair: "The operator has adjusted the linkage" becomes "The operator adjusted the linkage." The present perfect is not an approved tense; use the simple past.*
>
> ```bash
> # Non-STE: "The build has compiled the module before the test runs."
> # STE: the build compiled the module. Then the test runs.
> make build && ./run-tests
> # The build compiled the module. Then the test runs.
> ```

> **Non-STE:** The migration is to be run before you deploy the service.
> **STE:** Before you deploy the service, run the migration.
>
> *Adapted from spec pair: "The seat is to be installed before you install the cushion" becomes "Before you install the cushion, install the seat."*
>
> ```bash
> # Non-STE: "The migration is to be run before you deploy the service."
> # STE: before you deploy the service, run the migration.
> ./manage.py migrate   # run the migration first
> ./deploy.sh           # then deploy the service
> ```

> **Non-STE:** The cache can be cleared.
> **STE:** You can clear the cache.
>
> *Adapted from spec pair: "The volume control can be adjusted" becomes "You can adjust the volume control."*
>
> ```python
> # Non-STE: "The cache can be cleared."
> # STE: you can clear the cache.
> def clear_cache(handle: CacheHandle) -> None:
>     """You can clear the cache with this function."""
>     handle.flush()
> ```

> **Non-STE:** The timeout must be set before the job starts.
> **STE:** Set the timeout before the job starts.
>
> *Adapted from spec pair: "The temperature must be adjusted" becomes "Adjust the temperature."*
>
> ```yaml
> # Non-STE: "The timeout must be set before the job starts."
> # STE: set the timeout before the job starts.
> job:
>   timeout_seconds: 300   # set the timeout before the job starts
>   retries: 2
> ```

> **Non-STE:** The report will be generated by the scheduler.
> **STE:** The scheduler will generate the report.
>
> *Adapted from spec pair: "The sleeve will be adjusted by the robot" becomes "The robot will adjust the sleeve."*
>
> ```go
> // Non-STE: "The report will be generated by the scheduler."
> // STE: the scheduler will generate the report.
> func (s *Scheduler) Run() {
>     report := s.BuildReport() // the scheduler will generate the report
>     s.Send(report)
> }
> ```

> **Non-STE:** The service has restarted after the config change, so the clients have reconnected.
> **STE:** The service restarted after the config change. Then the clients reconnected.
>
> *Adapted from spec principle: convert the present perfect ("has restarted", "have reconnected") to the simple past ("restarted", "reconnected").*
>
> ```bash
> # Non-STE: "The service has restarted ... the clients have reconnected."
> # STE: the service restarted. Then the clients reconnected.
> systemctl restart api
> # the service restarted after the config change
> # the clients reconnected
> ```

> **Non-STE:** The error log must be checked before the release is approved.
> **STE:** Check the error log before you approve the release.
>
> *Adapted from spec principle: "must be <verb>-ed" becomes a command in the active voice. See Rule 3.6.*
>
> ```bash
> # Non-STE: "The error log must be checked before the release is approved."
> # STE: check the error log before you approve the release.
> ./check-logs --since 24h || exit 1   # check the error log
> git tag -a v2.1.0 -m "release"        # then approve the release
> ```

> **Non-STE:** The backup will be verified by the cron job at midnight.
> **STE:** The cron job will verify the backup at 00:00.
>
> *Adapted from spec principle: "will be <verb>-ed by <actor>" becomes simple future with the actor first.*
>
> ```cron
> # Non-STE: "The backup will be verified by the cron job at midnight."
> # STE: the cron job will verify the backup at 00:00.
> 0 0 * * *  /usr/local/bin/verify-backup.sh
> ```

> **Non-STE:** The input is to be validated before the record is written to the database.
> **STE:** Validate the input before you write the record to the database.
>
> *Adapted from spec pair: "is to be <verb>-ed" becomes a command. Keep the order clear.*
>
> ```sql
> -- Non-STE: "The input is to be validated before the record is written."
> -- STE: validate the input before you write the record to the database.
> BEGIN;
>   IF NOT is_valid(p_payload) THEN
>     RAISE EXCEPTION 'invalid input';   -- validate the input first
>   END IF;
>   INSERT INTO records (payload) VALUES (p_payload);  -- then write the record
> COMMIT;
> ```

> **Non-STE:** The dependencies can be installed with the package manager.
> **STE:** You can install the dependencies with the package manager.
>
> *Adapted from spec pair: "can be <verb>-ed" becomes active voice with a named actor ("you").*
>
> ```bash
> # Non-STE: "The dependencies can be installed with the package manager."
> # STE: you can install the dependencies with the package manager.
> npm install      # you can install the dependencies with the package manager
> ```

> **Non-STE:** The feature has been deprecated and will be removed in the next release.
> **STE:** The feature is deprecated. The next release removes the feature.
>
> *Adapted from spec principle: "has been deprecated" is present perfect (not approved). "deprecated" is an approved adjective (Rule 3.3); keep it as an adjective and use the simple future for the action. See Rule 3.3.*
>
> ```python
> # Non-STE: "The feature has been deprecated and will be removed in the next release."
> # STE: the feature is deprecated. The next release removes the feature.
> @deprecated("use send_v2 instead")
> def send(payload): ...
> ```
