# .agents — Agent-Agnostic Pipeline Skills

Role-based, self-contained skills for the STE-Code pipeline. Any agent can read
any prompt or skill and act in that role.

## Purpose
This directory holds everything the pipeline needs apart from the spec text:
orchestration scripts, agent prompts, capability skills, the benchmark suite,
and shared references. The pipeline transforms `ste-code/` (ASD-STE100 →
STE-Code) through staged workers; this tree is the machinery, not the output.

## Structure
```
.agents/
├── README.md                     ← This file
├── AGENTS.md                     ← Full agent/pipeline reference
├── MASTER.md                     ← Launch protocol + terminology
├── config/                       ← Shared config: defaults.yaml (agent+runtime), agents.yaml
├── tools/                        ← Orchestration scripts (one unit per stage)
│   ├── lib/                      ← Shared helpers (ste_io, ste_config, ste_runtime, …)
│   ├── <unit>/                   ← Each pipeline stage; owns config.yaml + README.md
│   └── runners/                  ← Phase runners (phase-a..f-run.py)
├── benchmark/                    ← Adversarial benchmark suite
├── skills/                      ← Capability skills (extraction, refinement, …)
├── prompts/  templates/          ← Worker prompts (externalized, not embedded)
├── references/                   ← Shared reference data (rails, worker grid, …)
├── state/  audit/  feedback/     ← Progress, auditor reports, inter-agent notes
```

## Pipeline (standardized stages)
Every stage shares one discipline: **orchestrated workers** (background, ≤3
concurrent, checkpointed, resumable) **+ a deterministic gate** that blocks bad
output **+ externalized prompts** (`templates/*.md` via `lib/templater.py`)
**+ tests**. Workers emit **markdown only**; JSON (where needed, e.g.
extensions) is derived deterministically — never generated by a worker (an
RCE-artifact remnant).

| Stage | Runner | Orchestrator | Gate / Verify | Output |
|-------|--------|--------------|---------------|--------|
| A Extract | `phase-a-run.py` | `extraction/extract_batch.py` | `verify_output` | `ste-code/extracted/` |
| B Refine | (agent) | `refinement/refine_batch.py` | SKILL gates | `ste-code/refined/` |
| B1 Continue | `phase-b1-run.py` | `continuation/continue_batch.py` | `verify-continuation` | `ste-code/refined/` (redo) |
| C Group | `phase-c-run.py` | `grouping/group_batch.py` | `verify-groups.py` | `ste-code/grouped/` |
| D Adapt | `phase-d-run.py` | `adaptation/adapt_batch.py` | `verify-adaptation.py` | `ste-code/adapted/` |
| E Extend | `phase-e-run.py` | `extension/extend_batch.py` | `verify-extensions.py` | `ste-code/extensions/` |
| F Artifacts | `phase-f-run.py` | `artifacts/artifact_batch.py` | `verify-artifacts.py` | `ste-code/artifacts/` |

Run order: **A → B → (B1 if needed) → C → D → E → F**. Each stage's runner
refuses to launch until its input directory is ready.

## Configuration (one source of truth)
All tunables live in config, never hardcoded in scripts:
- `.agents/config/defaults.yaml` — shared `agent:` (model, timeout, workers) and
  `runtime:` (retry_attempts, backoff_base_s, batch_divisor, encoding) knobs.
- `.agents/tools/<unit>/config.yaml` — the unit's own footprint (inputs,
  outputs, layout, agent overrides). Merged *under* defaults; the unit wins.
- A unit reads its config via `ste_config.load(__file__)`; pre-flight runtime
  knobs via `ste_runtime.resolve(__file__)`.

## Shared helpers (`tools/lib/`)
The single source for cross-cutting behaviour — no unit re-implements these:
- `ste_io` — **the only write path**; all writes confined to the repo by the jail
  policy (`write_text`, `write_json`, `mkdir`).
- `ste_config` — per-unit config resolution.
- `ste_runtime` — pre-flight resolution of wrapper/venv/retry/batch/encoding.
- `ste_checkpoint` — atomic checkpoint load/save for resume.
- `ste_paths`, `ste_time`, `ste_retry`, `ste_cli` — path, timestamp, retry,
  argparse helpers.
