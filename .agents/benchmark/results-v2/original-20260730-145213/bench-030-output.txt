# Use a specific Node.js base image
FROM node:18-alpine

# Set working directory
WORKDIR /app

COPY package*.json ./

# Install dependencies
RUN npm ci --production

COPY . .

---

**Compliance Summary**

| Issue | Severity | Fix Applied |
|---|---|---|
| `RUN npm install` without `package.json` present | **FATAL** — the build would fail at this line | Moved `COPY package*.json ./` *before* the install |
| No `WORKDIR` set | **HIGH** — files scatter in root, poor practice | Added `WORKDIR /app` |
| `node:18` tag is vague and pulls a full Debian image | **MEDIUM** — bloated image (~900MB vs ~120MB) | Changed to `node:18-alpine` |
| `npm install` in production contexts is non-deterministic | **MEDIUM** — version drift, slower installs | Changed to `npm ci --production` (reproducible, skips dev deps) |
| Comment said "before copying source code" but missed the package file nuance | **LOW** — misleading | Rephrased comments to distinguish package files from full source |
| Missing `COPY . .` to bring in app code | **FATAL** — container has no app to run | Added final `COPY . .` after dependency install |

**Key principle**: Docker layer caching works by copying `package.json` and `package-lock.json` first, then running `npm install`, *then* copying the rest of the source. This way, code changes don't invalidate the cached dependency layer — only package file changes trigger a reinstall.
