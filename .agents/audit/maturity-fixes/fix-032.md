**Example 2: `cache`**
- Test: Is it a specific named library? No — `cache` is a general concept.
- Test: Is it a generic algorithmic concept? Yes — caching is a computational pattern.
- Result: Cat 7 (Algorithmic and computational terms).
- But also: `CacheLayer` as a named class goes to Cat 6 (Modules, classes, components, and services). The lowercase `cache` is Cat 7. The PascalCase `CacheLayer` is Cat 6.

**Example 3: `race condition`**
- Test: Is it an error type or diagnostic state? Yes — it describes a concurrency bug.
- Result: Cat 14 (Error states, diagnostics, and health checks).
- But also: `race condition` could be Cat 18 (Bug taxonomy). Tie-break: if the term describes a detectable symptom or diagnostic state, use Cat 14. **Example 4: `middleware`**
- Test: Is it a URL, route path, or navigation primitive? Unclear — middleware handles requests but is not a path.
- Test: Is it a named class, module, or service? Maybe — middleware is often a function or module.
- Test: Is it an application operation concept? Yes — middleware handles requests in a pipeline.
- Result: Cat 8 (Routing, pathing, and state management) because middleware sits in the request routing layer.

## Edge Case Handling

### Term Fits Multiple Categories

When a term fits more than one category, use this order of priority:

1. **Context in source text.** Choose the category that matches how the term is used in the original STE example or the code-domain text you adapt.
2. **Specificity.** Prefer the most specific category. For example, a named library (`lodash`) goes to Cat 4, not Cat 19, because Cat 4 is more specific to dependencies.
3. **Capitalization.** PascalCase terms (e.g., `UserService`) go to Cat 6. lowercase terms (e.g., `hash`) go to Cat 7. UPPERCASE terms (e.g., `AWS`) go to Cat 5.
4. **If still uncertain**, use Cat 19 (Network, protocol, API, and I/O terms) as the default. Cat 19 is the broadest code-domain category and covers most general technical terms.

### Term Has No Clear STE Analogue

If a code-domain term has no clear STE category match:

1. Check if the term is a technical code noun (Rule 1.5—1.6). If yes, it belongs in this mapping.
2. Find the closest STE category by meaning, not by word. For example, `GraphQL` is not "navigation" but is an API protocol (Cat 19). `Docker` is not a "vehicle" literally, but it is a platform that hosts code (Cat 2).
3. If no STE category fits at all, use Cat 19 as the default.
4. Record the term and the chosen category in the Version History section. Include the date and the reason for the classification.

### New Code-Domain Terms Appear

When a new code-domain term appears that the Representative Examples column does not cover:

1. Classify the term with the Decision Table above.
2. Add the term to the Representative Examples column of the matching category.
3. Record the addition in the Version History section with the date and the term.
4. Do not create a new category number. All terms must map to one of the 19 categories.
