## Per-Section-Type Size Thresholds

The single ">3KB" threshold in the template is a rough baseline. Each
section type produces different output volumes. Use the table below to
check against the correct minimum for the page range.

| Section Type | Page Range | Minimum Size | Rationale |
|---|---|---|---|
| **FRONT** | 1-12 | >2KB | Large centered text, sparse layout. Copyright blocks and highlights tables are text-light. |
| **TOC / INDEX / INTRO** | 13-42 | >4KB | Narrative prose and table structures. TOC is sparser but INDEX and INTRO are dense. |
| **RULES / CATEGORIES** | 43-128 | >5KB | Highest text density. Every page has rule statements, explanatory paragraphs, and example pairs. |
| **DICT** | 129-360 | >3KB | Variable density. The 4-column PDF layout causes text interleaving. Some pages (e.g., letter Z) have few entries. Column artifacts reduce line count relative to content density. |
| **APPENDIX** | 361-434 | >3KB | Change history tables, flowcharts, index entries. Variable structure across appendices. |

NOTE: A file below its type threshold is a WARN signal, not an automatic
FAIL. Check the file content manually. A DICT file at 2.9KB for pages
355-358 (Q-Z tail) may be legitimate. A RULES file at 2.1KB for pages
100-103 is almost certainly truncated.

Cross-reference: see `.agents/references/section-types.md` for the full
page-to-type mapping and worker assignments.

## Spot-Check Methodology

The template says "check 3 random lines per file." Use the procedure
below to make this check reproducible and fair.

### Procedure

1. Pick 3 random non-blank lines from each file:

```bash
shuf -n 3 ste-code/extracted/wNNN-p*.md | grep -v '^$'
```

2. If any sampled line looks fabricated (commentary language, modern terms,
   wrong section), expand the sample:

```bash
shuf -n 5 ste-code/extracted/wNNN-p*.md | grep -v '^$'
```

3. Count failures across the 8 sampled lines (3 original + 5 expanded).
   If 3 or more of 8 lines fail, flag the file for re-extraction.

4. Record the seed for reproducibility:

```bash
# Use a fixed seed so others can reproduce the same sample
shuf --random-source=<(echo "batch12-w034") -n 3 ste-code/extracted/w034-p*.md
```

### Skip Rules

- Skip blank lines. They tell you nothing.
- Skip markdown formatting lines (`|---|`, `| Column |`). They are table
  structure, not content.
- If `shuf` is not available, use `sort -R | head -n 3` as a fallback.
- If the file has fewer than 10 non-blank lines, read all lines. The file
  is too small for random sampling to be meaningful.

### Interpretation

| Failures (out of 8) | Action |
|---|---|
| 0-1 | PASS. The file content is consistent with the source. |
| 2 | WARN. Check 5 more lines manually. If any of those 5 fail, escalate to re-extraction. |
| 3+ | FAIL. Flag for re-extraction. Log details in `ste-code/validation-log.md`. |

## Escalation Protocol

When a worker fails quality checks and re-extraction is needed, follow
this protocol.

### First Failure

Split the worker page range in half and re-extract both halves. See
`.agents/skills/validation/SKILL.md` for the re-extraction procedure.

### Second Failure (Same Worker or Its Replacement)

If the same page range fails extraction twice (original worker + one
re-extraction attempt, or both halves of a split fail), do not attempt
a third extraction. Instead:

1. Log full details in `.agents/feedback/exchange.md`:

```
## DEGRADED: Batch N, Worker WNNN (pages PPP-PPP)
- First failure: [Check number, reason, date]
- Second failure: [Check number, reason, date]
- Last 10 lines of output: [excerpt]
- Suspected cause: [truncation / empty page / corrupt source / model limit]
```

2. Mark the batch as **DEGRADED** in `.agents/state/PROGRESS.md`:

```
| N | WNNN-WNNN | PPP-PPP | ⚠️ DEGRADED — WNNN failed twice |
```

3. Proceed to the next batch. Do not block the pipeline.

4. The execution auditor (Agent #3) will triage all degraded batches at
   pipeline end. See `.agents/skills/auditing/SKILL.md`.

### Rationale

A worker that fails twice on the same page range signals a structural
problem (source page issue, model context limit, or content that
exceeds 4-page capacity). Retrying indefinitely wastes time. The auditor
has the full context to decide: manual extraction, page split, or
acceptance with noted gaps.
