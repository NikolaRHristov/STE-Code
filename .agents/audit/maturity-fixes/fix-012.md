# Merge Protocol — Stage 3 (Full Protocol)

Concatenate, deduplicate, and organize 109 worker files into a single master document. Agent-agnostic.

## When to Use
- After GATE 1 passes: all 109 worker files exist and have content
- Before adaptation begins

## Step 1: Concatenate by Page Range

Workers output in order (w001 covers 1-4, w109 covers 433-434):
```bash
cat ste-code/extracted/w*.md > ste-code/merged/master-raw.md
```

## Step 2: Deduplicate

Workers on adjacent page ranges may capture same content at boundaries:
- **Rule statements**: "Rule X.Y" with identical text → keep first occurrence
- **Example pairs**: Identical STE/non-STE pairs → keep first occurrence
- **Category listings**: Same category with same examples → keep from header page
- **Dictionary entries**: Same WORD (POS) with identical meaning → keep first

### Deduplication Algorithm

Use exact match after normalization. Do not use fuzzy matching.

**Normalization rules for comparison:**
1. Remove leading and trailing whitespace from each line.
2. Collapse two or more spaces to a single space.
3. Remove trailing blank lines from the block.
4. Keep the original indentation and line breaks.

**Detection by content type:**

| Content type | Match criteria | Scope |
|---|---|---|
| Rule statement | Rule number prefix + normalized body text | Cross-file |
| Example pair | Normalized STE line + normalized Non-STE line | Cross-file |
| Category listing | Category name + normalized example list | Cross-file |
| Dictionary entry | WORD (POS) + normalized meaning text | Cross-file |

**Priority for "keep first":**
- Compare the page range of each worker file.
- Keep the occurrence from the worker that covers the earlier page.
- If the page ranges are the same, keep the occurrence from the worker with the lower index (w001 before w002).

NOTE: Run deduplication after concatenation. Search the full `master-raw.md` for duplicates. Do not deduplicate per worker pair.

## Step 6: Edge Cases

### Boundary Content Disagreements

Adjacent workers may capture different text for the same page boundary. For example, w010 (pages 37-40) and w011 (pages 41-44) may both include page 40 content. If the two versions of page 40 differ:

1. Read the original spec page 40.
2. Compare both worker outputs to the source.
3. Keep the worker output that matches the source exactly.
4. Flag the mismatched worker for re-extraction.
5. If neither output matches the source, re-extract both workers.

### Cross-Referenced Rules

Some rules appear in more than one section of the spec. For example, a rule may be mentioned in Section 1 (Words) and cross-referenced in Section 6 (Descriptive Writing). When this occurs:

- Keep the full rule text in its primary section only.
- In the cross-reference location, add a note: `> See Section X — Rule Y.Z for the full text.`
- Do not duplicate the full rule text in the cross-reference location.

NOTE: The spec uses cross-references such as "Refer to Rule 1.1" within rule descriptions. Treat these as content to preserve. Do not remove them.

### Dictionary Entries with Different Formatting

Workers may format the same dictionary entry with small differences. For example:

Worker A:
```markdown
#### ACCEPT (v) — APPROVED
- **Meaning:** To receive or take something offered
```

Worker B:
```markdown
#### ACCEPT (v) — APPROVED
- **Meaning:** To receive or take something offered.
```

The only difference is a trailing period. Normalization removes this difference. After normalization, treat them as duplicates and keep the first occurrence.

If the MEANING text differs in substance (not just punctuation), flag both workers for review.

### Non-Contiguous Page Ranges

An extraction failure may cause a gap in the page sequence. For example, if w050 fails, pages 197-200 are missing from the concatenation.

**Detection:**
```bash
# Check that all 434 pages appear in master-raw.md
grep -oP "Page \d+" master-raw.md | sort -u | wc -l
# Must return 434
```

If the count is less than 434:
1. Find the missing page numbers.
2. Identify which worker is responsible for each missing page range.
3. Re-extract the missing workers.
4. Concatenate again from Step 1.

### Empty or Truncated Worker Files

Before concatenation, check each worker file:

```bash
# Find workers with fewer than the expected line count
for f in ste-code/extracted/w*.md; do
  lines=$(wc -l < "$f")
  if [ "$lines" -lt 30 ]; then
    echo "SUSPECT: $f has $lines lines"
  fi
done
```

A worker file with fewer than 30 lines is likely truncated or empty. Re-extract the worker before proceeding to concatenation.

## Step 7: Failure Recovery

### grep Count Mismatches

If any count in Step 4 does not match the expected number:

| Check | Expected | Recovery |
|---|---|---|
| Rule count != 53 | 53 rules | List all `#### Rule` lines. Find missing or extra rules. Check boundary workers for the missing sections. Re-extract affected pages. |
| Category count != 19 | 19 categories | List all `### Category` lines. Compare to the spec table of contents. Find the missing category and its responsible worker. |
| Dictionary count too low | ~2275 entries | Check if a worker range (A-Z) is missing. Look for gaps in the alphabetical sequence. Re-extract the missing letter ranges. |
| File does not start at Page 1 | "Page 1 of 434" | Check w001 output. The first worker must capture the title page. Re-extract w001. |
| File does not end at Page 434 | "Page 434 of 434" | Check w109 output. Re-extract w109 if incomplete. |

### Spot-Check Failures

If any of the 10 random spot-checks from Step 5 fails:

1. Identify the worker that covers the failing page.
2. Mark the worker as failed in PROGRESS.md: change `[x]` to `[!]`.
3. Re-extract the page range from the original spec.
4. Run Steps 1-4 again to regenerate master.md.
5. Repeat the spot-check for the same page number.

If 3 or more spot-checks fail, do a full re-extraction of all workers. Do not proceed to adaptation.

### File Size Below Threshold

If `master.md` is less than 500KB:

1. Check the size of `master-raw.md` first.
2. If `master-raw.md` is also small, the concatenation step missed files. Check the glob pattern in Step 1.
3. If `master-raw.md` is large but `master.md` is small, the organization step removed too much content. Compare line counts before and after organization.
4. Run:
   ```bash
   wc -l master-raw.md master.md
   ```
   The organized file must have at least 90% of the raw file's line count. If it has less, review the deduplication and organization logic.

### Worker Re-extraction Procedure

When a single worker must be re-extracted:

1. Launch the extraction agent for the specific page range.
2. Wait for the new worker file to appear.
3. Check the new file passes the line-count threshold (30+ lines).
4. Run the merge protocol from Step 1.
5. Do not skip deduplication on the re-run.

NOTE: If more than 5 workers need re-extraction, re-extract the entire batch instead of individual workers.
