## Edge Cases

### Non-POSIX Environment

The verification commands use `grep`, `wc`, and `head`. If these tools are
not available, use equivalent checks:

**Line count (alternative to `wc -l`):**
```python
python3 -c "print(len(open('OUTPUT_FILE').readlines()))"
```

**Glued headings (alternative to `grep`):**
```python
python3 -c "
import re
text = open('OUTPUT_FILE').read()
matches = re.findall(r'### [^\n]+\n[^ \n#]', text)
print(len(matches))
"
```

**Page header (alternative to `head`):**
```python
python3 -c "print(open('OUTPUT_FILE').readline().strip())"
```

### Short Extractions Below 30 Lines

The 30-line threshold assumes a 4-page extraction. Batch 37 (worker W109,
pages 433–434) extracts only 2 pages. For this worker, the line-count
check is not required. For other workers, an output below 30 lines is a
signal of incomplete extraction.

NOTE: If a page range change reduces the extraction below 4 pages, adjust
the line-count threshold to 7 lines per page (rounded up).

## Failure Recovery

When a rail check fails, the recovery action depends on the failure type.

| Rail | Failure Type | Recovery |
|---|---|---|
| **W1** (Page Header) | Missing or wrong header | Add the correct `# Page N of M` header. Do not re-extract. |
| **W2** (Glued Headings) | Heading glued to content | Add blank lines after headings. Do not re-extract. |
| **W3** (Fabrication) | Commentary, modern terms, summaries | Delete the file. Re-extract from the source pages. |
| **W4** (Boilerplate Control) | Repeated "ASD-STE100" text | Remove extra occurrences. Do not re-extract. |
| **W5** (STE/Non-STE Format) | Wrong example format | Fix the format to blockquote + bold label. Do not re-extract. |
| **W6** (Tables Clean) | Merged columns, missing separators | Split merged columns. Add separator rows. Do not re-extract. |
| **W7** (Blank Line After Tables) | Missing blank line | Add blank line after each table. Do not re-extract. |
| **W8** (Triple Blanks) | Three or more blank lines | Remove extra blank lines. Keep exactly one. Do not re-extract. |
| **W9** (Content Incomplete) | Missing words, numbers, examples | Delete the file. Re-extract from the source pages. |
| **W10** (Naming Wrong) | Wrong filename pattern | Rename the file to the correct pattern. Do not re-extract. |

adaptation, missing progress updates), see

## Design Rationale

### Why 10 Rails?

The 10 worker rails cover the 10 most common output defects found during
extraction and refinement:

- **Structural defects** (W1, W2, W7, W8): missing headers, glued headings, table spacing, blank lines
- **Content defects** (W3, W4, W9): fabrication, boilerplate spam, missing content
- **Format defects** (W5, W6): wrong example format, broken tables
- **Naming defects** (W10): wrong filename pattern

Ten rails is the smallest set that catches all known defect categories
without worker fatigue from an overly long checklist.

### Why a 30-Line Threshold?

A 4-page extraction produces approximately 7–10 lines per page. The
30-line threshold gives a safety margin:

- 4 pages × 7 lines = 28 lines (minimum for short pages)
- 30 lines = includes page header + one extra line for margin
- Output below 30 lines signals truncation, omission, or worker failure

### Why 4-Page Grouping?

The 4-page grouping balances two constraints:

1. **Worker context window**: Each worker reads source pages into context.
   More pages use more tokens and increase the risk of truncation.
2. **Batch throughput**: Fewer pages per worker means more workers (and
   more batches). 4 pages per worker gives 109 workers in 37 batches,
   completing in approximately 20–37 minutes.

The grouping is defined in
[`.agents/references/worker-grid.md`](worker-grid.md). Pages 1–432 use
4-page groups. The last batch (W109) uses 2 pages (433–434) because 434
is not a multiple of 4.
