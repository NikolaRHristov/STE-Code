### Batch Size Rationale

The batch size of 3 is an empirical optimum for the `deepseek-v4-pro` model.

- **Rate-limit constraint**: The provider enforces a concurrency limit. Three parallel `hermes -z` workers stay below this limit with a safe margin. More than 3 workers in one batch risks HTTP 429 responses and worker failures.
- **Model context constraint**: Each worker processes 4 pages in one model call. Three concurrent workers produce 12 pages of output per batch. This keeps the operator's review load manageable between batches.
- **Failure isolation**: If one worker in a batch fails, only 2 other workers are affected. A larger batch size (for example, 5 or 6) wastes more compute on re-extraction when a single worker fails.
- **Empirical validation**: Early extraction runs with batch sizes of 2, 3, 5, and 6 showed that 3 workers per batch gave the highest throughput with the lowest re-extraction rate.

### Partial Truncation Handling

If only some workers in a batch fail the truncation check (check #3):

1. Mark the passing workers as complete. Do not re-extract them.
2. For each failing worker, split its page range in half and re-extract with 2-page chunks.
3. If a single-page chunk still fails truncation, mark the file with a `[TRUNCATED]` annotation at the top. The refinement stage handles truncated files.
4. Do not block the pipeline for a single truncated worker. Continue to the next batch and flag the issue in PROGRESS.md.

## Known Limitations

NOTE: These limitations are expected and do not block the extraction pipeline.

### Formatting Variance

Workers can produce small differences in markdown formatting. For example, one worker can use `-` for bullet lists while another uses `*`. This variance is normal. The Refinement stage (Agent #2) normalizes all formatting to a single style.

### Table Rendering

Complex tables in the ASD-STE100 spec (for example, multi-column word tables with merged cells) can lose column alignment during extraction. The Refinement stage rebuilds these tables from the original spec pages.

### Page Boundary Artifacts

When a section spans across a 4-page boundary, the extracted text can have a small gap or duplication at the boundary. The Merge stage (Agent #3) detects and removes these artifacts.

### Last-Batch Edge Case

### Model Variability
