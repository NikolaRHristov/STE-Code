## Known Limitations

### Spec Page Availability

| Limitation | Impact | Mitigation |

### Model Limitations

| Limitation | Impact | Mitigation |
|------------|--------|------------|
| Model context window is smaller than 1M tokens | Workers with large page ranges (W5: 60 pages, W9: 74 pages) may truncate | Split large workers into sub-workers of 10-15 pages each. Use the granular strategy from `.agents/references/granular-strategy.md`. |
| Model is not `deepseek-v4-pro` | Extraction quality may drop; reasoning chains may be shorter | Run a benchmark mini-test: extract 3 known pages and compare output against a gold-standard JSON. If accuracy < 90%, do not proceed. |
| Model hallucinates spec content | Fabricated rules or dictionary entries enter `master.json` | GATE 2 spot-checks catch this. If spot-check pass rate < 90%, re-launch workers. Use rails from `.agents/references/worker-rails.md`. |

### Pipeline Limitations

| Limitation | Impact | Mitigation |
|------------|--------|------------|
| Worker batch of 3 is too slow (9 workers = 3 sequential rounds) | Total extraction time may exceed available session time | Increase batch size to 5 if the host has sufficient memory and CPU. Update Worker Launch Protocol. |
| `master.json` merge produces duplicates | Adapted artifacts contain redundant rules | After merge, run `python3 -c "import json; d=json.load(open('ste-code/extracted/master.json')); rules=[r['rule_number'] for r in d['rules']]; dups=[r for r in set(rules) if rules.count(r)>1]; print(f'Duplicates: {dups}') if dups else print('No duplicates')"` |
