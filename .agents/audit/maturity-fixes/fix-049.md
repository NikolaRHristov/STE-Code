## Edge Cases

### Missing Source Directory

If a worker cannot find a source directory listed in the Discovery Targets table:

1. The worker logs the missing path in the discovery log (see Discovery Log Format below).
2. The worker marks the target as "⬜ Blocked" in the status column.
3. The worker records the reason: "Source directory does not exist at `<path>`".
4. The worker moves to the next target in its assignment.
5. A coordinator re-checks the path on the next discovery run.

This applies to growing directories. The `SCE/core/rules/` and `ste-code/v2/core/rules/` directories may contain fewer files than listed in "Expected File Counts". The worker discovers what exists. It does not create files for missing content. If a directory exists but has fewer files than expected, the worker creates placeholders only for the files it finds. The worker notes the discrepancy in the discovery log.

### Unknown File Type

If a worker finds a file that matches no pattern in the skip list and is not a known translatable type (`.md`, `.txt`, `.prompt.md`):

1. The worker logs the file with type `unknown` in the discovery log.
2. The worker does NOT create a placeholder for the file.
3. The worker adds the file to a quarantine list: `translations/quarantine/<locale>/unknown-files.md`.
4. A human reviewer decides whether the file is translatable.
5. If approved, the file pattern gets added to a future discovery run.

The quarantine list format:
```markdown
# Quarantine — Unknown File Types — <locale>
| File Path | Extension | Size (bytes) | Discovery Date | Decision |
|-----------|-----------|-------------|----------------|----------|
| path/to/file.xyz | .xyz | 1234 | 2026-07-30 | Pending |
```

### Conflicting Shared Terms

When two locales produce different translations for the same STE-Code approved term (for example, the word "set" in `a-dictionary.md`):

1. The conflict is detected during the catalog merge step.
2. The Translation Orchestrator (Agent #9) flags the conflict in `translations/catalog.md`.
3. Each locale keeps its translation. The catalog records both versions.
4. A glossary cross-reference table tracks the divergence.
5. The Orchestrator does NOT force one locale to match another. Locale autonomy is preserved.

Catalog conflict entry format:
```markdown
### Conflict: "set" (verb)
| Locale | Translation | Context |
|--------|------------|---------|
| fr | définir | a-dictionary.md line 4230 |
| pt-BR | configurar | a-dictionary.md line 4230 |
> Status: Divergence accepted. Both translations are valid.
```

## Failure Modes & Recovery

### Wrong Encoding in Placeholder

If a worker creates a placeholder file with an encoding that is not UTF-8:

1. The catalog merge step runs an encoding check on all files.
   ```bash
   file -I translations/<locale>/**/*.md | grep -v 'utf-8'
   ```
2. Any non-UTF-8 file gets flagged in the catalog with a "⚠ Encoding" marker.
3. The worker that created the file is re-launched with an explicit encoding instruction: "Write output in UTF-8 encoding only."
4. If re-launch fails, the file is converted:
   ```bash
   iconv -f <detected-encoding> -t UTF-8 translations/<locale>/<path> > temp && mv temp translations/<locale>/<path>
   ```

### Locale Directory Structure Mismatch

If a locale directory does not match the expected layout (for example, `translations/ja/ste-code/` exists but `translations/ja/ste-code-v2/` is missing):

1. The catalog merge step compares each locale's structure against the placeholder layout.
2. Missing directories are flagged in the catalog with "⚠ Missing dir: `<path>`".
3. The worker for that locale is re-launched on the missing target only.
4. If re-launch fails twice, the locale is marked "⬜ Partial" in the catalog until the next discovery run.

### Worker Failure During Discovery

If a worker exits with an error or produces zero placeholder files:

1. Mark the worker's targets as "⬜ Failed" in this grid.
2. Check the discovery log for the worker's last output.
3. Re-launch the worker with the same prompt (as specified in `STE-CODE-IMPLEMENTATION.md` worker failure protocol).
4. If the worker fails twice, split its assignment: each locale gets its own worker.
5. Update the catalog with the failure details.

### Placeholder File Is Empty

If a worker creates a placeholder file but the file contains no content (zero bytes):

1. The post-batch verification detects zero-byte files.
   ```bash
   find translations/<locale>/ -name '*.md' -size 0
   ```
2. Zero-byte files are deleted and flagged in the catalog.
3. The worker is re-launched for the affected target.
4. If the same file is empty after two attempts, add a "⚠ Empty — manual review" entry and move on.
