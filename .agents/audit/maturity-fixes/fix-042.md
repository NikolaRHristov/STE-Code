## Design

**434 pages ÷ 4 pages per worker = 109 workers**
**109 workers ÷ 3 per batch = 37 batches**
**Each batch ~30-60s = ~20-37 minutes total**

### Design Rationale

**Why 4 pages per worker?** Each page in the spec holds 30-50 lines of text. Four pages give 120-200 lines of source material. This range is large enough to make efficient use of a worker invocation. It is small enough that the model does not truncate or summarize content. Workers extracting more than 4 pages (tested at 6 and 8 pages) start to omit examples or collapse tables.

**Why 3 workers per batch?** Hermes runs 3 terminal background processes at a time without resource contention on this hardware. Launching 3 at a time keeps the system under its memory and I/O limits. Larger batches (tested at 5 and 6 workers) cause worker timeouts and partial output. Smaller batches (1 or 2 workers) double the total wall-clock time with no quality benefit.

**Why 30-60s per batch?** Each worker reads 4 pages and writes one output file. This takes 20-40s for the model to process. The batch wait adds 10-20s of verification overhead. Total per batch is 30-60s. Worst-case: 37 batches × 60s = 37 minutes. Typical: 37 batches × 30s = 18.5 minutes.

## Worker Prompt Template (per worker)

Every worker prompt includes the worker rails from `.agents/references/worker-rails.md`.
These rails are appended to each prompt. Workers self-validate before they write output.

```bash
hermes -z "Read spec/issue-09-2025/page-NNNN.md through page-NNNN.md. Extract ALL content exactly into ste-code/extracted/wNNN-pPPPP-PPPP.md. Do not summarize. Include every word, every table, every example. Output ONLY the markdown file." -m deepseek-v4-pro --yolo
```

### Rails Integration

Workers launched from this grid must follow two rail sets:

| Rail Set | File | Scope |
|----------|------|-------|
| Worker Rails | `.agents/references/worker-rails.md` | Per-worker validation. 10 self-check rails. Injected into every prompt. |
| Process Rails | `.agents/references/rails.md` | Cross-worker rules. 8 process-level rails. Stage isolation, naming, completion integrity, content fidelity, formatting, facts, progress, error recovery. |

The launch script reads `worker-rails.md` and appends it to each worker prompt. The orchestrator validates batch results against `rails.md` after each batch completes.

## Launch Script

A shell script generates and launches all 109 workers in 37 batches:
1. Generate prompt for each worker. Append worker rails from `.agents/references/worker-rails.md`.
2. Launch 3 at a time via terminal background.
3. Wait for batch completion. Run verification gates before proceeding.
4. git gcommit-hermes after each batch.
5. Continue to next batch.

### Verification Gates (per batch)

Before a batch is marked complete, the launch script checks these gates:

| Gate | Check | Action on Failure |
|------|-------|-------------------|
| **G1: File Exists** | Each of 3 output files exists on disk. | Mark worker as failed. Go to error recovery. |
| **G2: Minimum Size** | Each output file is larger than 3KB and has more than 30 lines. | Mark worker as truncated. Go to error recovery. |
| **G3: Clean Ending** | Last 3 lines of each file end on sentence boundaries. No mid-word truncation. | Mark worker as truncated. Go to error recovery. |
| **G4: Rails Pass** | Each file passes the 10 worker rails from `worker-rails.md`. | Mark worker as rail violation. Go to error recovery. |
| **G5: No Fabrication** | File contains no fabrication signals (commentary language, modern terms, missing headers). See `rails.md` RAIL 4 for detection signals. | Mark file as fabricated. Delete and re-extract. |

### Error Recovery Procedures

When a worker fails a verification gate, use these procedures:

| Failure Mode | Recovery Procedure |
|--------------|--------------------|
| **Timeout (no output file)** | The worker did not produce a file. Restart the same worker with identical parameters. If it fails again after 2 retries, go to Split Recovery. |
| **Truncated output (file too small or cut off)** | The worker started but did not finish. Split the page range in half. Launch 2 replacement workers: one for the first 2 pages, one for the last 2 pages. Name output files as `wNNNa-pPPPP-PPPP.md` and `wNNNb-pPPPP-PPPP.md`. |
| **Fabricated content** | The worker added commentary or invented terms. Delete the output file. Re-extract from source with a stricter prompt: "Extract ONLY the exact text. Add zero commentary. Add zero modern terms." |
| **Rail violation (formatting)** | The content is correct but the format is wrong. Do not re-extract. Send the file to Stage 2 (Refinement) for format correction. Add a note in PROGRESS.md. |
| **Worker failed twice (same range)** | Skip the range after 2 retries. Mark it in PROGRESS.md as `[!]`. Resume from next batch. Return to skipped ranges after all 37 batches complete. |

### Batch Status Codes

| Code | Meaning | Action |
|------|---------|--------|
| `[x]` | Batch complete. All gates passed. | Continue to next batch. |
| `[!]` | Batch has failures. Recovery in progress. | Execute recovery procedure. |
| `[s]` | Batch skipped after 2 retries. | Return later with split pages. |
| `[ ]` | Batch not yet started. | Launch workers. |
