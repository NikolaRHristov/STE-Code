### Step 2: Deduplicate

Workers on adjacent page ranges may capture the same content at boundaries.
Use these patterns to identify duplicates:

- **Rule statements**: "Rule X.Y" followed by identical text → keep first occurrence
- **Example pairs**: Non-STE/STE pairs that are identical → keep first occurrence
- **Category listings**: Same category with same examples → keep from the page where the category header appears
- **Dictionary entries**: Same WORD (POS) with identical meaning → keep first occurrence

#### Concrete Deduplication Procedure

Do not rely on manual scanning alone. Run these automated checks first, then review manually.

**Check 1 — Duplicate rule headers:**

```bash

  | sort -t: -k2 \
  | uniq -d -f1
```

If output is empty, no duplicate rule headers exist. If lines appear, each line shows a duplicate.

**Check 2 — Rule count anomaly:**

```bash
# Count unique rule headers
```

## Edge Case Catalog

These cases occur rarely. Handle them as specified.

### EC-1: Missing Worker File After GATE 1

**Symptom**: `ls ste-code/extracted/w*.md | wc -l` returns < 109, but GATE 1 tracker shows all 109 complete.

**Cause**: File was deleted or moved after GATE 1 verification.

**Action**: Identify missing worker numbers. Check extraction batch logs in `.agents/state/`. Re-launch extraction for those page ranges only. Do not proceed with merge until count returns to 109.

### EC-2: Two Workers Disagree on Boundary Page Content

**Symptom**: w042 and w043 both cover page 168, but text differs (one has a typo, or paragraph order differs).

**Cause**: Page 168 spans a physical page turn. Worker w042 may have captured an incomplete sentence at page bottom; w043 may have captured the full paragraph.

**Action**: Go to source spec `spec/issue-09-2025/page-0168.md`. Compare both worker outputs against source. Keep the output that matches source exactly. Flag the other for re-extraction.

### EC-3: Dictionary Entry with Conflicting POS Tags

**Symptom**: "ABOUT" appears as `(prep)` in one worker and `(adv)` in another.

**Cause**: Valid. ASD-STE100 Issue 9 assigns some words multiple approved parts of speech. ABOUT is both a preposition and an adverb.

**Action**: Keep both entries. Do not collapse. Verify against the official dictionary if uncertain.

### EC-4: Empty Worker File with Non-Zero Name

**Symptom**: `ls -l` shows `w067-p265-268.md` with size 0 bytes.

**Cause**: Worker launched but produced no output (timeout, crash, or model error).

**Action**: Remove the empty file. Re-extract pages 265-268. Do not include empty files in concatenation.

### EC-5: master-raw.md Corrupted During Concatenation

**Symptom**: File exists but contains binary characters, truncation at a random byte, or encoding errors.

**Cause**: Disk full during write, filesystem error, or source file with non-UTF-8 content.

**Action**: Delete master-raw.md. Check disk space (`df -h .`). Re-run concatenation. If error persists, bisect: concatenate in halves to find the corrupt worker file.

### EC-6: Page Ranges Have Gaps

**Symptom**: w001 covers 1-4, w002 covers 5-8, but w003 covers 13-16 (pages 9-12 are missing).

**Cause**: Extraction batch misconfiguration. Worker numbering is sequential but page ranges skip.

**Action**: Stop merge. Map page coverage: run `for f in ste-code/extracted/w*.md; do echo "$f: $(head -1 "$f")"; done`. Identify the gap. Re-extract the missing pages as new worker files (use the next available wNNN number, note the anomaly in PROGRESS.md).

### EC-7: master-raw.md Exceeds Expected Size

**Symptom**: File size > 800KB instead of expected ~500KB.

**Cause**: Massive duplication across many boundary pages (rare), or a worker file was concatenated twice.

**Action**: Check for duplicate worker files: `ls ste-code/extracted/w*.md | sort | uniq -d`. Check for duplicate content density: `wc -l ste-code/merged/master-raw.md`. Expected ~15,000-20,000 lines. If significantly higher, run dedup checks from Step 2.
