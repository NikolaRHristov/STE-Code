## Failure Modes and Recovery

### Mode 1: PROGRESS.md is stale

**Signal**: Disk shows different file counts than PROGRESS.md claims.

**Recovery protocol**:

1. Record the discrepancy in the Errors & Blockers table.
2. Note the specific batch or worker that is mismatched.
3. In the Next Actions section, add an item to update PROGRESS.md.
4. After you write the state report, update PROGRESS.md with these rules:
   - If a file is missing but PROGRESS.md shows [x], change the marker to [!].
   - If a file exists but PROGRESS.md shows [ ] or is absent, add or check the entry.
   - Add a timestamp comment at the top of PROGRESS.md: `> **Stale entry fixed:** YYYY-MM-DD HH:MM:SS — [description of fix]`.
5. Mark R7 (Progress Tracking) as FAIL in the Rails Compliance table.

### Mode 2: Truncated worker output

**Signal**: A file is below 3KB or ends mid-word.

**Recovery protocol**:

1. Record the file in the Errors & Blockers table as 🟠.
2. Add a Next Action: "Re-extract [worker ID] with split page range."
3. If the worker covered pages N to N+3, split into two workers: N to N+1 and N+2 to N+3.
4. Do not delete the truncated file until the new extraction succeeds.

### Mode 3: Fabrication detected

**Signal**: Output contains fabrication signals per Rail 4 (modern terms not in the spec,
commentary language, wrong facts).

**Recovery protocol**:

1. Record the file in the Errors & Blockers table as 🔴.
2. Delete the fabricated file immediately.
3. Add a Next Action: "Re-extract [worker ID] from source spec pages."
4. Mark R4 (Content Fidelity) as FAIL.
5. Check sibling worker outputs for the same fabrication pattern.

### Mode 4: Wrong working directory

**Signal**: `find ste-code/` returns 0 files but you know the pipeline exists.

**Recovery protocol**:

1. Run `pwd` to confirm the current working directory.
2. If you are not in the pipeline root, change to it before running any commands.
3. Use `ls ste-code/` to confirm you are in the correct location.
4. If you cannot find the pipeline root, write "UNKNOWN — cannot locate pipeline root" in
   the agent identity section and stop. Do not produce a report from the wrong directory.
