## Edge-Case Handling

During adaptation, you may encounter problems with the source data in
`ste-code/merged/master.md`. This section defines how to handle each
problem without fabricating or halting the pipeline.

### Missing or Corrupt Rule Entries in master.md

**Symptom**: A rule number (e.g., Rule 3.5) is listed in the master.md
index but its content section is empty, truncated, or unparseable.

**Action**:
1. Log the gap: write the rule number and the problem to
   `.agents/state/ADAPTATION-GAPS.md`.
2. Skip the rule. Do NOT fabricate content to fill the gap.
3. Continue to the next rule.
4. After all 53 rules are processed, return to gaps. Attempt to find
   the missing content in `ste-code/refined/` or `ste-code/extracted/`.
5. If the content cannot be recovered from earlier stages, mark the
   rule as `⚠️ BLOCKED` in PROGRESS.md and note the reason.

### Duplicate or Colliding Rule Numbers

**Symptom**: Two different adaptation attempts produce files with the
same rule number (e.g., `a-sec2-rule2.3.md` written twice with different
content).

**Action**:
1. Check if the collision is from a previous incomplete run (check
   `git log` for the file history).
2. If a previous run produced a partial file, overwrite it with the
   complete adaptation.
3. If two genuinely different rules claim the same number, check
   master.md to determine which is correct. The incorrect one gets
   renamed with a `-alt` suffix and a note in ADAPTATION-GAPS.md.
4. Never leave two files with the same rule number in `ste-code/adapted/`.

### Incomplete Synonym Table

**Symptom**: The synonym table in master.md has fewer entries than expected,
or some canonical pairs are missing their "avoid" column.

**Action**:
1. Adapt every complete pair that exists. Do not delete incomplete pairs.
2. For rows where the "avoid" column is empty, keep the "prefer" word
   and add `[AVOID COLUMN MISSING IN SOURCE]` as a placeholder.
3. Log all incomplete pairs to ADAPTATION-GAPS.md.
4. In the artifact generation stage (Stage 5), omit incomplete pairs
   from the final synonym table. Only emit complete pairs.

### Incomplete Polysemy Resolution Table

**Symptom**: Same as synonym table — entries with missing resolution data.

**Action**:
1. Same procedure as incomplete synonym table.
2. Polysemy entries are more critical than synonym entries because
   unresolved polysemy causes ambiguity. Flag these with higher
   severity in ADAPTATION-GAPS.md.

### Category Count Mismatch

**Symptom**: master.md lists a number of categories other than 19, or
category-mapping.md has a different count.

**Action**:
1. The authoritative count is 19 (verified against ASD-STE100 Issue 9
   pages 47-52).
2. If master.md claims a different count, trust the spec pages. Log the
   discrepancy to ADAPTATION-GAPS.md.
3. If category-mapping.md has more or fewer than 19 rows, flag it.
   The mapping file is the reference for adaptation — if it is wrong,
   adaptation output will be wrong. Fix category-mapping.md first (or
   alert the operator to fix it) before proceeding.

### File Write Failure

**Symptom**: `write_file` or shell redirect fails (disk full, permission
denied, path does not exist).

**Action**:
1. Check disk space: `df -h ste-code/`
2. Check directory exists: `mkdir -p ste-code/adapted/ ste-code/artifacts/`
3. Retry the write once.
4. If it fails again, log to ADAPTATION-GAPS.md and continue to the
   next file. Do not loop indefinitely.
