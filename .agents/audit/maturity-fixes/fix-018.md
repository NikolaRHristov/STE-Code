## Scoring Formula

```
score = 0.40 (base)
      + 0.60 × (principles_satisfied / expected)     ← 60% weight
      − 0.30 × (forbidden_found / total_forbidden)    ← penalty
      + 0.10 × (keywords_found / total_expected)      ← bonus
      − 0.20 × (patterns_missed / total_patterns)     ← gen-only
```

Pass threshold: ≥ 0.70

### Script Details

`orchestrator.py` runs all 59 test cases in parallel. Each test runs in a CWD-isolated `hermes -z` session with the full STE-Code system prompt. The script sends each test case to `deepseek-v4-pro`, collects the output, and scores it against the expected criteria. Results land in `.agents/benchmark/results/run-{timestamp}/`.

`orchestrator-control.py` runs the same 59 tests without the STE-Code system prompt. It uses a plain assistant prompt instead. This produces a baseline for comparison. Results land in `.agents/benchmark/results-control/run-{timestamp}/`.

`rescore.py` re-scores previously saved outputs from a completed run directory. Use this after you change the scoring formula or fix a test case definition. It does not call `hermes -z` again.

### Edge Cases

**Worker timeout.** If a test worker does not complete within its configured timeout, the orchestrator records a score of 0.00. The per-test result shows `"error": "timeout"`. Re-run only that category with a longer timeout.

**Empty output.** If the agent returns no text, all principle checks fail. The score drops to the base 0.40 minus any forbidden-keyword deductions (none found in empty text). The result shows `"output_length": 0`.

**Truncated output.** If the response hits the `max_tokens` limit, patterns at the end of the text may be cut off. Generation tests with missed patterns lose up to 0.20. Increase `max_tokens` in the test case definition and re-run.

**Partial re-run.** To re-run one category only, filter the test case file by `category` field. Pass only that subset to the orchestrator. Alternatively, run the full suite and later re-score with `rescore.py` after fixing the test definition.

**API errors.** If `hermes -z` fails with a non-zero exit code, the orchestrator records the test as unscored. The aggregate report counts these as failures. Check network connectivity and API key validity before retrying.

### Troubleshooting

| Signal | Meaning | Corrective Action |
|--------|---------|-------------------|
| Score < 0.70 | Test failed the pass threshold | Check `expected_principles` and `forbidden_keywords`. Re-read the output for violations. |
| Forbidden keywords found | Non-approved words leaked into output | Review the STE-Code dictionary (Rules 1.1, 1.6). Replace forbidden terms with approved synonyms from the canonical table. |
| Patterns missed (generation tests only) | Output did not contain the required code structure | Check the prompt clarity. Make sure the generation task describes the expected structure. |
| Score = 0.40 (exactly) | Base score only — zero principles matched | Verify that the agent received the STE-Code system prompt. Check for empty or completely off-topic output. |
| Score < 0.40 | Penalties exceeded the base score | Output contains many forbidden keywords. Check for slang, jargon, or non-approved verb forms (Rules 1.10, 1.4). |
| Two consecutive runs produce different scores | Non-deterministic model output | Accept the variance. Use the average of three runs for high-stakes decisions. |
