## Edge-Case Handling

### Already Well-Formatted Input

Some extracted files may already follow most of the 9 rules — especially pages
with only dictionary entries or simple tables. When a worker receives input
that needs minimal changes:

1. The worker MUST still produce a refined output file (no skip).
2. Run verification as normal.
3. If checks C1–C3 pass and C4–C9 show zero issues, the file is a refinement
   no-op. Mark it complete and move on.
4. Do NOT re-extract or re-refine a file that already passes all checks.

### Broken Markdown Output (Structural)

A worker may produce output that passes the line-count check (C2) but contains
structurally invalid markdown. Check C8 (unclosed fences) catches the most
common defect. Additional structural flaws to watch for:

- **Nested code fences**: A ` ``` ` inside another ` ``` ` block. Detect with:
  ```bash
  grep -n '^```' ste-code/refined/rNNN-p*.md | head -20
  ```
  Look for non-alternating fence lines (two consecutive opens without a close).

- **Broken table separators**: A header row without `|---|` on the next line.
  Detect with manual inspection — no simple grep pattern catches this.

- **Malformed blockquotes**: `>` lines missing the trailing space before content.
  Detect with:
  ```bash
  grep -n '^>[^ ]' ste-code/refined/rNNN-p*.md
  ```

If C8 or any structural defect is found: flag as BLOCKING and re-run the worker.

### Truncated Input from Extraction Failure

If the input file (`ste-code/extracted/wNNN-p*.md`) is itself truncated due to
an extraction failure (detected at Stage 1):

1. Do NOT attempt refinement on a truncated input.
2. Check the input file size before refinement:
   ```bash
   wc -l ste-code/extracted/wNNN-pPPPP-PPPP.md
   ```
   If fewer than 20 lines or under 1 KB, flag the file.
3. Re-extract the pages first (return to Agent #1), then refine.

### Worker Produces No Output or Empty File

If a worker launches but produces an empty or missing output file:

1. Check if the worker crashed:
   ```bash
   ls -la ste-code/refined/rNNN-p*.md
   ```
2. If the file is missing: re-launch with the same prompt.
3. If the file exists but is empty (0 bytes): re-launch with the prompt split
   into two 2-page workers instead of one 4-page worker.
4. If the same page range fails twice: split into 4 single-page workers.

### Batch-Level Contingency

If any worker in a batch fails BLOCKING checks:

1. Re-launch ONLY the failed worker (not the whole batch).
2. If the same worker fails twice, split its 4-page range into 2+2.
3. Do NOT hold the rest of the batch — already-passing workers stay complete.
4. Track re-runs in REFINE-PROGRESS.md with a `🔄` marker.
