  - Completion verification is multi-step: count check (109 files), zero-byte check, gap check, rails check, spot-check of 3 random files for "..." omissions
  - Concrete launch command with model lock (`deepseek-v4-pro` exclusively)
  - Cross-references 5 skill/reference files

  - No meta-instructions for self-improvement - the rules are treated as immutable with no mechanism to evolve them
  - No measurable quality gates beyond ">3KB" and "spot-check 3 random files" - no automated content checks (e.g., count of STE/Non-STE pairs per page, dictionary entry count validation, heading depth consistency)
  - No rationale for why these 9 rules in this order, or why certain formatting decisions (e.g., `####` for dictionary entries vs `**bold**`)
  - Edge cases for unusual input unaddressed: mixed languages in source, corrupted table cells, deeply nested lists, pages with no headings, pages that are pure tables
  - No performance considerations: token budget per worker, expected runtime, cost estimate
  - Cross-references are listed but their existence/adequacy is never verified
