### .agents/skills/execution-auditor/SKILL.md
- **Level:** 3
- **Summary:** Hidden verification agent skill that audits other agents' completion claims against disk evidence. Defines a 5-step audit protocol (collect claims, collect evidence, cross-reference, flag discrepancies, produce report), fabrication detection patterns, and an auto-fix mode for safe, known pattern remediation (22→19, stale file cleanup, model name corrections).
- **Strengths:**
  - 5-step audit protocol with concrete command snippets and shell examples for each step
  - Discrepancy flagging table maps 8 specific mismatch types to severity levels (🔴 CRITICAL / 🟠 ERROR / 🟡 WARNING) with precise definitions
  - Fabrication detection patterns table with 6 signal types and their meanings - specific enough to grep for
  - Fix mode is a distinct, well-scoped subsection with fixable/unfixable pattern tables, fix protocol steps, and a launch prompt - covers the edge case of safe vs. unsafe remediation
  - Audit report format template fully specified with section-by-section content requirements
  - Single-prompt launch and fix-mode launch prompts provided verbatim
  - Cross-references to rails.md, PROGRESS.md, and feedback/exchange.md - all exist on disk
- **Gaps:**
  - No explicit rationale for why the 30-line / 3KB threshold was chosen as the content signal cutoff, or what edge cases that threshold might miss
  - No performance considerations - what does a full audit of 109+ files cost in tokens/time? When should a partial audit suffice?
  - No version history, changelog, or indication of when the fixable patterns list was last updated
  - No known limitations - e.g., fabrication detection relies on keyword matching and cannot detect AI-generated spec text that avoids the listed patterns
  - No measurable quality gates (e.g., "audit completes with ≤3 false positives per 100 claims" or similar)
  - No meta-instructions for self-improvement - the fixable patterns table is hardcoded and has no mechanism for adding newly discovered patterns
- **What Level 4 Would Add:** Explicit rationale for design decisions (threshold choices, why these 6 fabrication patterns), performance considerations (token cost estimates for full vs. partial audits, guidance on sampling strategies), known limitations with workarounds (e.g., "keyword-based fabrication detection has a blind spot for paraphrased AI content - spot-check 3 random files manually per audit"), and a section on how to extend the fixable/unfixable pattern tables when new patterns emerge.
- **Priority:** low
