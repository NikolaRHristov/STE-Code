## Critical Rules

1. **Batch size: 3.** Never launch more.
2. **Verify after every batch.** Never skip verification.
3. **Commit after every batch.** `git gcommit-hermes`.
4. **Never delete existing files.** Only add to `expanded/` or modify in-place with additive changes.
5. **If a batch fails:** check `RECOVERY-NEEDED/`, re-launch with narrowed scope.
6. **Track everything.** Flip [ ] → [x] in FINAL-PASS-TRACKER.md after each batch.

## What NOT To Do
- ❌ Use `hermes -z` via `subprocess.Popen` — unreliable stdout capture. Use oneshot wrapper.
- ❌ Run more than 3 workers per batch — overwhelms API, causes timeouts.
- ❌ Delete existing files — always add to `expanded/` subdirectories.
- ❌ Trust PROGRESS.md without verifying files on disk.
- ❌ Skip verification after a batch — JSON output must be validated before continuing.
- ❌ Use `sed` for file edits — use `patch` tool or Python scripts preserved in scripts/.
